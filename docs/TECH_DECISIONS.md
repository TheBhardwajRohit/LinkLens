# Tech decisions

Every stack choice, and the reason for it. At the end of the project, this file is the answer to "why this stack?".

**Status:** *Decided* = agreed with Rohit (2026-09-24).

| # | Area | Choice | Why | Alternatives considered | Status |
|---|---|---|---|---|---|
| 1 | Website hosting | GitHub Pages | Free, lives in the same repo, and Rohit wanted GitHub. Static files only, which fits because our backend is separate. | Vercel, Netlify (also free, but another account) | Decided |
| 2 | Scheduled jobs | GitHub Actions | Free and in the repo (public repo, so no minute limit on standard runners). Each run gets a fresh throwaway VM, which is a safe, isolated place to visit scam pages (safety rule 10). GitHub's terms make data-collecting cron a gray area; Rohit accepted that risk. | Cron on a VM, Celery beat | Decided |
| 3 | Database + screenshots | Supabase (free plan) | A real Postgres database (what the plan needs), plus file storage for screenshots and a read-only API the static website can use. All in one free account. | Neon (Postgres only, no file storage); JSON files in the git repo (size limits, every save is a commit, parallel jobs clash) | Decided, account not created yet |
| 4 | Live scan server | Docker containers, on Rohit's PC for now | GitHub can't run a server, and Actions' terms forbid using it as part of a serverless app. Containers move to any host unchanged, so the host can be picked later. | Free cloud hosts, to compare in phase 10 | Decided for now; host still open |
| 5 | Website framework | Vite + React + TypeScript | The site is a static single-page app talking to a separate API. Next.js's main extras (server rendering, API routes) don't work on GitHub Pages, so Vite gives the same React ecosystem with less setup. | Next.js static export (works, but most of its features go unused); Astro | Decided |
| 6 | Styling and motion | Tailwind CSS, Motion (the new name of Framer Motion) | Fast to build a consistent dark theme; smooth card animations, scroll effects, and tilt, with built-in reduced-motion support. | Plain CSS, GSAP | Decided |
| 7 | 3D hero graph | react-three-fiber (Three.js), glossy instanced spheres and "rails", studio-light reflections | The standard way to do WebGL in React. Instanced meshes draw every node and link in two draw calls, so it stays fast. The graph shows real scan data, not decoration. | Plain Three.js; CSS dots (the first idea, but we'd have thrown it away) | Decided |
| 8 | Maps and graphs | Cytoscape.js (network map), Leaflet + OpenStreetMap (server map) | Both free, no API keys, and built for exactly these jobs. | D3 force graph, Mapbox (needs a key) | Decided |
| 9 | API | Python + FastAPI | Python has the analysis libraries we need (TLSH, pHash, DNS, graphs, ML). FastAPI handles many lookups at once (async), checks inputs, and supports live progress. | Node + Express (weaker analysis libraries), Django (heavier) | Decided |
| 10 | Sandbox browser | Playwright + Chromium, own container | Records redirects, every network request, and screenshots. Well maintained, with a Python API. | Puppeteer (Node only), Selenium (less network detail) | Decided |
| 11 | Job queue | None at first (no Celery, no Redis) | Scheduled work runs on Actions. The scan server has one user and low volume, so FastAPI background tasks are enough. Fewer containers also make free hosting easier. Add arq or RQ with Redis if scans start piling up. | Celery + Redis (from the original brief) | Decided |
| 12 | Live progress | Server-Sent Events | One-way updates from server to browser. Simpler than WebSockets, and works over plain HTTP. | WebSockets, polling | Decided |
| 13 | Local dev database | Postgres in Docker | Tests run offline, without touching shared data or free quotas. It's the same Postgres Supabase uses. | Supabase CLI local stack (many containers) | Decided |
| 14 | Icons | lucide-react | Clean, consistent line icons; only the ones we use end up in the bundle. | Hand-drawn SVGs, Heroicons | Decided |
| 15 | Fonts | Red Hat Display (headings), Red Hat Text (body), self-hosted via Fontsource (changed from Space Grotesk and Inter in the redesign, to match the OneText look) | Self-hosting means no requests to Google Fonts, so visitors aren't tracked and the security policy stays strict. | Google Fonts CDN, system fonts | Decided |
| 16 | Website tests | Vitest | Built for Vite, so tests reuse the same config and run in under a second. | Jest (needs extra setup with Vite) | Decided |
| 17 | Page security | Content Security Policy added at build time | The browser refuses any script, style, or connection we didn't list, which blocks most injected code. This matters most in phase 4, when results from scam pages are shown. | No policy (GitHub Pages can't set security headers, so a meta tag is the only option) | Decided |
| 18 | 3D loading | three.js loaded lazily, with an error guard and a frame-rate check | three.js is about 245 kB compressed. Loading it after the page appears keeps the first paint fast. If it fails or runs under 24 frames a second, the page quietly switches to a flat SVG version of the same graph. | Always load 3D; 3D only | Decided |
| 19 | SSRF protection | Our own filtering proxy in the sandbox, plus a guard that checks every resolved IP | Checking a URL once isn't enough: redirects, images, scripts, and DNS answers that change (DNS rebinding) can all reach private addresses later. Forcing every browser connection through a proxy that connects to the exact IP it checked closes all of those at once. | Checking only the first URL; Playwright request interception (can't pin the IP); firewall rules on the host (hard on Docker Desktop) | Decided |
| 20 | Redirect kinds | Chromium's own debugging protocol (CDP) reports why each navigation started | Reading each page's HTML misses instant script redirects, because the page is gone before it can be read. Chromium knows the real reason (meta tag, script, Refresh header, form). HTML reading stays as a backup. | HTML parsing only | Decided |
| 21 | Browser identity | Normal desktop Chrome user agent string, same version | Headless Chrome announces itself as "HeadlessChrome", and many scam kits show a harmless page to anything that does. A normal string is what other URL scanners use. We still never solve or get around CAPTCHAs. | Default headless string | Decided |
| 22 | HTTPS errors in the sandbox | Ignored while visiting | Scam sites often have broken or self-signed certificates. Refusing them would hide the page we're trying to analyze. Phase 3 checks the certificate itself and reports problems. | Refuse bad certificates | Decided |
| 23 | Sandbox tests | Run inside the sandbox image with networking off | Same Chromium as real scans, and the tests provably can't reach the internet (safety rule 9). A tiny local server serves made-up pages; a fake resolver maps test names to addresses. | Tests on the host with a separately installed browser | Decided |
| 24 | Homepage design | Split hero inspired by OneText: content left (60%), live graph right (40%), overlapping dark panel below | Puts the one thing people come to do (paste a link) at the top, and gives the visual its own space instead of sitting behind the text. The graph tells a story in speech bubbles, like OneText's chat bubbles, but with scan data. | Original brief layout (name, cards, then input at the bottom) | Decided |
| 25 | Graph layout | Our own small force simulation (about 150 lines) | Fewer than 50 nodes, so the simple version is fast. It's seeded, so the same scan always gets the same layout, and the same code drives the 3D and the flat fallback. No extra library. | d3-force-3d, react-force-graph (much bigger) | Decided |
| 26 | Domain registration data | RDAP (IANA's bootstrap list picks the right server), with plain WHOIS only for registries that have no RDAP | RDAP is structured JSON and the official successor to WHOIS, so parsing is reliable. Some popular scam TLDs (.io, .co) still lack RDAP, so a small WHOIS fallback covers them. Written in-house (about 150 lines) instead of adding a client library. | python-whois, whoisit | Decided |
| 27 | Server location and owner | MaxMind GeoLite2 City + ASN, read from local files; IP RDAP for the network name and abuse contact | Local lookups are instant, with no per-scan limits, and nothing about a scan is sent to MaxMind. The files refresh weekly (their terms require updates within 30 days). RDAP adds who to report abuse to. | DB-IP Lite (no sign-up, slightly less accurate), online IP APIs (rate limits, send every IP away) | Decided |
| 28 | Certificate history | crt.sh first, Cert Spotter as the backup | crt.sh has the full history (including expired certificates, which shows how long a domain has been around) but is often slow or down; it was down on the day we built this. Cert Spotter is free for personal use and reliable, but lists current certificates only, and the page says so. | crt.sh only; Censys (needs an account) | Decided |
| 29 | DNS lookups | Public resolvers (1.1.1.1, 8.8.8.8) first, then the system resolver; each record type fails on its own | Docker's built-in DNS helper stalled for seconds on some queries (NS for github.com), which sank the whole lookup. Public resolvers answered in milliseconds. Only domain names are sent, same as normal browsing. Override with `DNS_RESOLVERS`. | System resolver only | Decided |
| 30 | TLS certificate capture | In the sandbox, through a separate connection checked by the SSRF guard | Reading the certificate means contacting the site, which only the sandbox may do. Playwright's own security details don't include the names on the certificate, so the sandbox reads the full certificate itself (with the `cryptography` library) and also checks whether a normal browser would trust it. | Playwright security details only (no names, no trust check) | Decided |
| 31 | Scoring (v1) | Hand-written rules, each a plain-words reason with points; good signs subtract | Every point on the score can be explained to a person, which matters more than a slightly better number at this stage. Phase 9 adds a trained model on top and keeps the reasons. | A trained model from day one (no labeled data yet, and it can't explain itself) | Decided |
| 32 | Brand list | Hand-made JSON of 60+ brands scammers copy (global and Indian), with official domains and search words | Small, reviewable, and easy to extend. Only real banks and government bodies can register .bank.in and .gov.in, so those count as official automatically. | A big automatic list (many false alarms on ordinary words) | Decided |
| 33 | Popularity signal | Tranco top 100,000, refreshed monthly | A research ranking built to resist manipulation. It also stops popular sites that contain a brand's name (icicidirect.com) from being called lookalikes. Free-hosting platforms are ranked as a whole, so their individual sites are judged separately. | Alexa (discontinued), Cisco Umbrella list alone | Decided |
| 34 | Saving scans | Postgres with plain SQL (psycopg), one `scans` table with a JSON column | One table and three queries don't need an ORM or migration tool yet. JSON keeps the full result without a schema change every phase. Screenshots sit in their own column so the JSON stays small. | SQLAlchemy + Alembic (worth it once the schema grows, likely phase 6) | Decided |
| 35 | Live progress | In-memory jobs streamed as Server-Sent Events; polling as the fallback | One-way updates are all the page needs, and SSE works over plain HTTP with built-in browser support. Jobs are kept 15 minutes, so a slow page can still catch up. No queue or Redis needed yet. | WebSockets, Redis pub/sub | Decided |
| 36 | Privacy of saved scans | Emails, tokens, and session IDs removed from every stored link; shared links always show the cleaned copy | Links often carry personal data (reset tokens, emails). Only the person who ran the scan sees the link exactly as pasted, in their own live stream. | Storing links as pasted | Decided |
| 37 | Blacklist sources | Google Safe Browsing (key set), Phishing.Database lists checked locally, urlscan.io search (no key needed). VirusTotal and URLhaus are built and switch on when a free key is added. | Each source answers a different question: Google covers phishing and malware at scale, Phishing.Database is a big free list we can check without sending anything out, urlscan.io shows whether others have looked at the site. Every source always ends with a plain status, so a missing key or a used-up quota never breaks a scan. | Paid feeds; PhishTank (sign-ups closed) | Decided |
| 38 | Blacklist timing | The pasted link is checked first, before the sandbox opens it; the final page and the stops in between are checked again during recon | Gives a first answer in about 2 seconds. Scam links often hide behind shorteners, so the real destination needs its own check. Links already checked come from the cache. | One check at the end | Decided |
| 39 | Lookup cache | Memory first, plus a `lookup_cache` table in Postgres | VirusTotal allows 500 free checks a day and 4 a minute, so answers must survive restarts. Google's "listed" answers are kept exactly as long as Google says (its `cacheDuration`). | Memory only (lost on restart); Redis (one more service) | Decided |
| 40 | Phishing lists in memory | A sorted array of 8-byte hashes, searched with binary search | About 450,000 entries cost under 4 MB this way; a plain Python set of strings would need around 60 MB. A false match would need two entries to share a 64-bit hash, which is practically impossible at this size. | Python set of strings; loading the lists into Postgres (500 MB limit on the free plan) | Decided |
| 41 | What leaves the server during a check | Links with emails, tokens, and session IDs removed; only the site name goes to urlscan.io; private-address stops are never sent | Safety rule 7. Lookups still match, because blacklists list the host and path, not someone's personal token. | Sending links as pasted | Decided |
| 42 | Google's key in a header | `x-goog-api-key` header, not `?key=` in the address | HTTP libraries log request addresses. A key in the address could end up in a log file. | Key in the query string (Google's examples) | Decided |
| 43 | Page fingerprints | TLSH of the HTML, an exact hash and a 64-bit similarity hash (simhash) of the tag sequence, a simhash of the visible words, pHash of the screenshot, MurmurHash3 of the favicon | Each one survives a different kind of change. TLSH tolerates edited code, the tag hashes ignore the words, the word hash ignores the layout, pHash catches pages that only look alike, and the favicon catches kits that keep their icon. A match needs at least two of them to agree. | ssdeep (left out: the pure-Python build is slow, and TLSH gives a graded distance); TF-IDF vectors stored per page (too big for a 500 MB database, so the 40 most used words are kept instead) | Decided |
| 44 | Finding similar pages fast | Each 64-bit hash is cut into four 16-bit pieces stored in one `bands` array with a GIN index | Two hashes that differ in three bits or fewer always share a piece, so one indexed query finds the candidates and only those are compared in full. No special database extension is needed. | Comparing against every stored page (too slow); a vector database (one more service) | Decided |
| 45 | Favicon capture | The sandbox loads the icon in a second tab of the same browser | That way the icon request goes through the same filtering proxy and SSRF guard as the page. Only its bytes are hashed; it is never opened as an image or shown. | Fetching it from the API (breaks safety rule 1); Playwright's request API (may skip the proxy for local names) | Decided |
| 46 | What is stored per page | Fingerprints, a few facts for finding siblings (IP, network, registrar, name servers, certificate names), the page's most used words, the sites it links to, and a 240 px thumbnail | Roughly 1 kB a page plus a few kB of thumbnail, so a few hundred thousand pages fit in the free database. Raw HTML is never stored. Feed thumbnails are dropped after 30 days. | Storing HTML or full screenshots (size, and it would mean hosting scam pages) | Decided |
| 47 | Dataset loading | PhreshPhish streamed from Hugging Face, read in windows of 256 rows by a pool of worker processes | The 36 GB dataset never touches the disk. One pass produces both the fingerprints (for families) and the feature file (for the model). Runs in Docker or on Actions, never straight on Windows, where the antivirus may quarantine phishing HTML. | Downloading the dataset first | Decided |
| 48 | Feed ingestion on Actions | Three jobs: plan (may read the database), visit (no secrets, `permissions: {}`), store (database and MaxMind key) | The job that opens live scam pages has nothing worth stealing. It fingerprints the pages itself, so raw HTML never becomes a GitHub artifact; only fingerprints and a thumbnail are passed on. | One job with everything (a misbehaving page could reach the database secret) | Decided |
| 49 | Schedule switch | The hourly schedule is skipped unless the repository variable `INGEST_ENABLED` is `true` | Without a shared database there is nowhere to store pages, and hourly runs that throw their work away would waste GitHub's free minutes. | Always running | Decided |
| 50 | No keep-alive | Dropped the planned "keep-alive" for scheduled workflows | GitHub pauses schedules after 60 days without repository activity. The best-known keep-alive action was taken down by GitHub staff for breaking the terms of service, so working around the pause is not allowed. If it ever happens, GitHub sends an email and one click (or `gh workflow enable`) turns the schedule back on. | A keep-alive commit or API call (against GitHub's terms) | Decided |
| 51 | Features for the model | 82 numbers read from the link and the page only; popularity rank and "this is the brand's real site" are left out | Research datasets hold a link and its HTML, nothing about who registered the domain. And because the benign half is mostly popular sites, a model given popularity would only learn "unpopular means scam". The rules still use popularity as a good sign. | Feeding the model everything | Decided |
| 52 | What counts as "the same design" | Points for each kind of fingerprint that agrees (code, structure, wording, look, icon); a match needs 3 points from at least 2 kinds, and one of them must be about content (wording, look, or icon) | Site builders such as Wix or Google Sites give thousands of unrelated pages the same code and structure, so those two alone prove nothing. One lucky match (the same default icon, the same tiny error page) must never link two pages. Requiring two independent kinds to agree keeps false links rare, and the same rule is used by the nightly grouping and by live scans. | A single threshold on one hash | Decided |
| 53 | Grouping into families | Connected components over those links, with candidates found through shared hash pieces. In big buckets each page is compared with a few neighbours and anchors, not with everyone. | On 55,000 pages this takes about 12 seconds, and the dataset's own brand labels show the groups are clean (see PROGRESS.md), so the heavier Leiden or HDBSCAN step is not needed yet. Groups that are mostly ordinary pages (a blog theme, a parked-domain page) are skipped as common templates. | Leiden or HDBSCAN from the start (more to tune, no clear gain at this size) | Decided, revisit when families start to chain |
| 54 | Family numbers | A family's number is the id of its oldest page | The number then stays the same from one night to the next, so "Family #12" in a saved report still means the same family later. | Renumbering every night | Decided |
| 55 | Sibling sources | Our own page library, the certificate (names on it and on its history), registration details, urlscan.io's public history for the IP address, and DNS for lookalike names | All public records, and none of them visits a site. Networks where one address serves thousands of sites (Cloudflare, Fastly, Akamai, GitHub Pages) are named as such and earn no points. | A paid reverse-IP service | Decided |
| 56 | Lookalike names | Up to 90 small variations of the name (another ending, a dropped or doubled letter, swapped neighbours, look-alike characters, an added hyphen or digit), each looked up in DNS | Shows which neighbours of a name really exist, in about two seconds, without opening any of them. The report says plainly that existing does not mean scam. | dnstwist (a whole extra tool for the few rules we need) | Decided |
| 57 | Link graph | SiNMULI's Algorithm 2 on the scanned site's neighbourhood only: edges signed by the site they start at, the balance rule for unknown signs in triangles, then the 51% vote over incoming links | Follows the paper (read on arXiv, 2608.19190v1) and stays fast because only a few dozen sites are involved. It abstains when links are few or disagree, which is the honest answer for most new domains. | Running it over the whole library on every scan (slow, and no better for one site) | Decided |
| 58 | Graph library | NetworkX in the API | Small graphs, so plain Python is fast enough, and it has PageRank, eigenvector centrality, and clustering built in. | igraph (faster, but one more compiled library in the scan server) | Decided |
| 59 | Network map | Cytoscape.js, loaded only when a report has links to draw; names appear on hover or click, with the same content as a plain list underneath | Canvas drawing copes with dozens of nodes, drag and zoom come built in, and the list keeps it usable without a mouse or with a screen reader. The page's security policy allows exactly one inline style by its hash: the one-line rule Cytoscape adds. | D3 force layout (more code), drawing our own | Decided |
| 60 | Server map | Leaflet with OpenStreetMap tiles, loaded only after the visitor clicks "Show on a map" | The tiles come from OpenStreetMap's servers, the only third party the site ever talks to, so the visitor chooses. OpenStreetMap's tile rules are followed: their exact tile address, visible credit, no bulk loading. A dot is drawn instead of Leaflet's pin image. | Always showing the map (a third-party request on every report); a static world image (no zoom) | Decided |

## Sources we chose not to use

| Source | Why not |
|---|---|
| OpenPhish academic feed | Approval is slow and access is time-limited. Rohit's choice: skip it. |
| PhishTank | New user registration has been closed since 2020. |
| OpenPhish community feed (off by default) | Its terms (read 2 Oct 2026) allow personal and academic research only and forbid passing the data, or anything made from it, to third parties. A public site that shows matches would do exactly that. The code can read the feed, but it stays off unless `FEEDS` names it. |
| URLhaus as an ingestion feed | Its links are malware downloads, not pages, so the sandbox would stop at the download and there would be nothing to fingerprint. URLhaus stays a lookup only. |
| URLhaus bulk downloads without a key | Every abuse.ch download and API now needs a free Auth-Key. Without one, URLhaus shows "not set up". |
